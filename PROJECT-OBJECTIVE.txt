OBJECTIVE

Build a website — a personal, all-in-one study hub for SSC CGL Tier-1 exam
preparation. Follow both the FORM below and all the FEATURES below — only
the visual THEME / look / layout-style is free to choose, and can be
different each time.

FORM (do not change this — only vary the visual theme/layout-style within it)
- Multi-page app: every section has its own route/page (e.g. /today, /pyq,
  /notes, /mistakes, /mocks, /vocab, /plans, /settings) — NOT a single-page
  tab-switcher where everything changes via client-side state.
- Styling: plain hand-written CSS. Do not use Tailwind or any UI component
  library (shadcn/MUI/chakra/bootstrap/etc.). Keep all colors/spacing as
  "design tokens" (CSS custom properties) in one central CSS file — the
  entire theme should be changeable by editing just that one file's token
  values, with every other CSS rule reading from those tokens.
- Content: do NOT write or hardcode any sample/seed/mock questions — not
  even a few for demo purposes. Questions will be supplied separately
  afterward. Instead, only build the loading mechanism: a single file —
  `public/data/questions.json` — that the app reads at runtime. It may
  start as an empty `[]`; whenever data in the shape below is placed there,
  the app should display it:
    [{ "id": string, "subject": string, "chapter": string,
       "question": string, "options": string[], "answer": number (0-based
       index), "explanation": string }, ...]
  If the file is empty or missing, do not crash — show an empty state
  ("No questions loaded yet") with a fully working UI otherwise (just an
  empty list).
- Other content (notes, current affairs) the same way — no hand-written
  sample data in code; start from an empty file/array, meant to be filled
  at runtime.
- Data: static JSON data-files (question banks, organized by subject/
  chapter) — no database/backend.
- State: stored in the browser's localStorage (progress, mistakes,
  settings) — no login/account/server.
- Navigation: a collapsible/drill-down side menu (opening a group reveals
  its items), top level shows only names — not a flat top navbar.
- Quiz-taking: ONE reusable "quiz player" component opened from everywhere
  (PYQ chapter, mock, notes-quiz, auto-practice) — don't build a separate
  quiz engine per page.

CORE IDEA
On opening, immediately show "what to do today"; practice for all 4
subjects (Maths, Reasoning, English, GS) available in one place; any
wrong/skipped question automatically lands in a "mistake list"; work
resumes exactly where it was left off.

1) DAILY HOME — today's target and how much is done (subject-wise
progress); one button generates an auto practice set (weaker chapters get
more weight); an option to manually log an externally-taken mock; a small
"study feed" (vocab/notes) that the user curates themselves.

2) CURRENT AFFAIRS — daily/monthly/yearly content, each entry has a video
+ quiz; importing new content auto-generates its quiz; for a daily
revision habit, an unprompted current-affairs question pops up in the
background occasionally.

3) PYQ PRACTICE BANK — several separate question banks (a mixed exam-wise
bank, a large English bank, an error-spotting bank, a large Maths bank, a
newer Maths bank, a Reasoning bank, small GK topic banks); an "all in one
place" view where picking a subject shows every bank's questions for it in
one list; each bank is organized into chapters, each chapter split into
fixed-size sets (results remembered); the user can also create their own
question-books and have them appear in this same section.

4) NOTES LIBRARY — several separate study-notes books, browsable by topic;
one large GS book containing 9 sub-subjects together; for any page without
a Hindi/Hinglish version yet, a small "add it" reminder (so pages that
already have notes don't get buried); a quick-reference short-rules
section; a static-GK topics section (each topic with its own quiz+video).

5) PRACTICE & TEST-BUILDING — build a mixed test by picking chapters and
count yourself; a ready-made topic-wise quiz bank; a separate mock-tests
section (full+sectional, results tracked); a quiz for every notes-book
from one page; create your own chapters/rules/questions to practice with;
one common player that runs any quiz; a distraction-free fullscreen
one-question-at-a-time mode; a separate speed-math drill.

6) MOCK MARKS TRACKER — record each mock's section-wise correct/wrong/
total/time; score/accuracy/attempted auto-calculated; percentile from
rank+total candidates; option to view by subject.

7) MISTAKE / ANSWERS NOTEBOOK — any wrong/skipped question lands here
automatically; can also paste in a screenshot from an external source
along with an answer brought in from elsewhere; all questions sit in one
rotating list — oldest on top, just-handled at the bottom, but ONLY when
the user explicitly presses "done" (merely picking an option or reading
the answer must not move it); chapter-tagging plus a report of which
chapter has the most mistakes; a separate list of questions that took too
long; a separate list of answers brought in from elsewhere; a handwriting/
stylus mode for solving by hand.

8) VOCABULARY — day-wise batches of word-meaning practice, each batch has
a quiz; add new words yourself from content; a one-at-a-time list of
words you've personally caught, where you can type/paste in the meaning;
bookmark important words.

9) LONG-TERM STUDY PLANS — a fixed multi-week plan that tells you day by
day what to study, with daily tracking and a streak; a separate "one
subject, entire syllabus, revised repeatedly" multi-pass plan (each pass
a bit faster than the last).

10) SETTINGS — enter and test your own AI key; back up/restore all data
as one file; automatic sync across devices via a secret code; a panel for
building your own question-books; track focused study time; a light
reminder for the #1 pending priority task.

CROSS-CUTTING
Should work offline and sync when back online; leaving a quiz mid-way and
returning should resume exactly there; every question's attempt history
should be recorded (weak-area detection/reports are built from this); able
to connect to an external helper tool that sends in mock screenshots and
answers from outside; should feel like an installable app, with some
content downloadable for offline use.
